# Toy Town battle-end collision query

Generated by Codex (GPT-6.1 sol).

## Scope and measured failure

A player's stopped app on Toy Town map 149 reaches `getTileTrigger` from
`renderDropShadow` during `BTL_deinitializeCombat`. Read-only inspection finds retiring
entity slot 3/type 76 at (2808, 0, -5242), tile (78, 102), index **0x2826**. Its
on-map/on-screen flags remain set. Both diagnostic attaches detached safely; no player
memory, saves or preferences were written. The stopped process log has no GameShark action.

US symbols give `MAP_COLLISION_DATA = 0x801AF398` and `STDVS_CAMERA = 0x801B1B98`.
Index 0x2826 therefore reads **0x801B1BBE**, byte 2 of `STDVS_CAMERA.coord.flg`.
PS1 `GsVIEW2` is 32 matrix bytes plus a four-byte pointer, putting the flag at camera
byte 36. Native pointers widen that view to 40; the camera is 160 native bytes versus
140 on PS1. Extending the native array into that object would not preserve PS1 bytes.
The observed camera word was zero, but a constant-zero workaround would be incorrect.

## Bounded correction

- Preserve the raw span and guard **unchanged**: `-0xE000 <= i < 0x2800`.
- A read-only query view models exactly **0x2824..0x2827**, the four bytes of the named
  flag. Rust uses generated `StdVsCamera` fields to read the current C-owned scalar,
  then extracts the requested little-endian byte. No pointer serialization, native
  offset constant, default-zero value or cached flag is used by the shipping reader.
- The companion decomp routes only native `getTileTrigger` reads through that view.
  Non-native queries expand to the original array access. Movement collision checks,
  raw indexing/writes and every other unmodelled neighbor keep their previous guard.
- No save, entity, script, position, game rule, SPU, UI or GameShark changes.
