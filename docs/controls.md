# Live keyboard mapping (proposed macOS feature)

Generated by Codex (GPT-6.1 sol).

## Scope and controls

**Controls → Keyboard Mapping…** opens a native macOS modal window containing an embedded,
local-only HTML/SVG keyboard editor. All fourteen original digital controller buttons have
one physical-key capture field. The diagram depicts the logical buttons, not a hardware
controller configuration tool: **this feature remaps keyboard keys only**.

Click a field (or focus it and press Return), then press its replacement. Escape cancels
capture. Duplicate assignments swap the two buttons, keeping both reachable. Restore
defaults brings back Z/X/A/S, arrows, Return, Right Shift, Q/W and 1/2. Numpad Enter may be
explicitly chosen instead of Return; buttons have no hardcoded extra aliases.

The game pauses while editing. Bindings save immediately, and the game uses them after the
window has closed and focus returns, without a process restart. Keys held across editing
must be released/repressed. In the USA release, Cross confirms and Triangle goes back;
Circle is not the generic cancel button (`decomp/include/dw/input.h`).

The existing SDL gamepad layout path is retained, and no physical-controller remapping is
introduced. **Only a keyboard was available for manual testing. Physical-controller input
and behavior across the editor were not tested.** Automated mapping tests are not hardware
verification.

## Implementation and persistence

- `crates/dw1/src/controls.rs`: explicit DOM-code/SDL-scancode allowlist, single-key bindings,
  conflict swaps, physical held state, versioned JSON and transactional preference updates.
  Unknown/reserved keys and duplicate/missing bindings on disk are rejected.
- `controls/macos.rs`: main-thread `objc2` AppKit menu/NSWindow and WebKit message bridge.
  The menu target is retained and uninstalled before release. WebKit uses a nonpersistent
  data store; its message-handler retention cycle is broken on close.
- `controls/editor.html`: original unbranded SVG geometry and inline UI. No logo, third-party
  artwork, game assets, downloaded font or runtime web resources were imported. CSP denies
  resource loads/connections, automatic script windows are disabled, and drops are prevented.
  Rust validates the bridge's button/key names; UI state is serialized JSON, not raw markup.
- The modal loop does not call the game host, so it advances no game fields. Existing Pacer
  resync handles the wall-clock gap; queued audio may drain. Closing restores game focus.
- All polling loops (game, splash, disc picker) clear held state on editor revisions and reject
  input timestamped at/before modal close, using SDL monotonic nanoseconds. Fresh input in
  the same poll is retained. Focus loss also clears held state. Lifecycle events are kept.
- `~/Library/Application Support/dw1-silicon/controls.json` is separate from saves and picture
  settings. A same-folder PID-specific temporary file is renamed on successful write. A save
  failure shows an error and leaves the old mapping active. Malformed input is not rewritten
  merely by loading it; defaults are used with an explanation in the editor.
- `DW1_CONTROLS_FILE` overrides the preferences path for isolated tests. Headless/replay hosts
  never instantiate the window and do not read keyboard preferences. Disc, save formats and
  emulated game/SDK logic are not changed.
- Command/Control/Option shortcuts, Escape and the existing F2–F5/F11/F12 hotkeys are reserved.
  Labels describe physical US-layout positions, not layout-dependent typed characters.

## Verification

- `cargo test --workspace --locked` on the clean upstream-based branch: **238 passed,
  0 failed, 27 ignored**. `cargo build --release -p dw1 --locked` also succeeds.
  Fixture-dependent skipped tests are not new oracle certifications.
- New unit tests cover defaults/no aliases, live rebind/release, conflict swaps, JSON round
  trips, reserved/unknown keys, malformed preferences, transactional writes/failures,
  unambiguous key/scancode tables, independent held keys/clearing, SVG button coverage and
  preserving the first post-close key in the same poll. The last regression fails with the
  original whole-poll discard and passes with timestamp filtering.
- Native menu/WebKit UI checks: key capture, swaps, F12 rejection, Escape cancellation,
  reopening and process-relaunch persistence, reset, Done/red-close, focus return, input
  release and capture isolation. The classic outline was revised following player feedback.
- Real-game keyboard checks, not just `--controls-preview`: temporarily changing Up to I
  immediately moves the title cursor and makes the old Up inactive. In a separate actual
  game process with isolated preferences and an empty isolated save directory, Cross was
  rebound to L and then Period without relaunching; the first press after observing the
  editor close opens the New Game slot list, and the former key is inactive. Triangle/Quote
  returns to the title menu. The player subsequently confirmed the revised feature works.
- Manual keyboard runs used the same keyboard code in a local build also carrying the
  independent Techsheet fix (#3). The clean-branch tests/build above exclude that patch;
  this PR changes no SDK code and does not depend on it.
- A key sent before the asynchronous modal close was observed did not register that first
  press. These checks wait for the setting window to disappear and game focus to return;
  they do not claim input sent while editing/closing should drive the game.
- **Keyboard only: no physical controller was available to test.** No full playthrough,
  physical-controller, VoiceOver, multi-display/fullscreen or new oracle-replay certification
  is claimed. No independent model review is claimed unless separately recorded in the PR.

## Disc-free manual smoke test

```sh
DW1_CONTROLS_FILE=/tmp/dw1-keyboard-test.json target/release/dw1 --controls-preview
```

Use the menu, change Cross to `/` and Circle to `.`, click Done, wait for the window to close,
and press/release them. The host shows current PadRead and last nonzero bits (0040 and 0020);
released input is 0000. Reopen, test duplicate swapping and Restore defaults, and relaunch
for persistence. This mode does not load a disc, initialize the game or open save slots.
Use a preferences path distinct from normal play. This contribution is independent of
SDK/Techsheet fixes.
